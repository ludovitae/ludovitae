# v1.2.2 — Field-tested against real money (2026-07-12)

Tag: `v1.2.2`. The release where the owner pointed it at his actual financial
life — real accounts, real institution exports — and it held up.

## The headline

The owner ran the full field-test checklist (#11) against real data from four
institutions (Fidelity, American Express, Citi, Commerce Bank). Every import
format was handled, accounts auto-created and auto-matched, and — the proof of
the whole credit-card model — **card payments auto-paired across institutions**
(Amex/Citi charges reconciled against Commerce checking legs), so nothing
double-counted as spending. Real data surfaced (and fixed) bugs no synthetic
fixture had, including a `csv.Sniffer` misparse on Amex's multiline fields.

## Features

- **Import creates & matches accounts** (#26): unseen accounts are created
  from the wizard (works from an empty database — the cold-start blocker is
  gone); OFX and multi-account CSVs link by hashed account id and auto-route
  on re-import. Four **built-in institution presets** ship (Fidelity, Amex,
  Citi, Commerce) — first import of each auto-matches by header fingerprint.
  Split debit/credit (both sign conventions), pending-row skipping, embedded
  newlines, preambles/footers, padded payees all handled. Investment-account
  activity is excluded from spending analytics.
- **Start from scratch** (#27): Settings danger zone — reset to demo data or
  erase everything (backup taken first, password/settings preserved); a
  first-run choice of demo vs empty.
- **Per-account detail pages** (#30): edit type/owner/institution/asset class/
  freshness, balance history, this-account transactions, external-link status,
  and an "import into this account" shortcut. Type changes show their
  consequences before you save.
- **Forecast explainability** (#29): a "how this is computed" panel (recurring
  components, variable-spending window, per-month breakdown) and a Plan-tab
  explainer showing where simulation saving actually comes from.
- **Fixes**: compact-money rounding boundary (#6), write-time person-data
  validation (#7).

## Infrastructure & hardening

- **Container image + pipeline** (#14): `ghcr.io/ludovitae/ludovitae`,
  UBI9 multi-stage, podman-first, quadlet-ready; published on every release.
- **Wheel bundles the web UI** (#13): `pip install ludovitae` serves the app.
- **Security pass over the v1.2 surface** (#12,
  docs/SECURITY-REVIEW-v1.2.md): no critical/high; fixed an export that
  leaked password/session hashes; SHA-pinned all CI actions.
