# Architecture

Owner: lead architect (coordinator session). Changes here require a note in
`docs/DECISIONS.md`.

## System overview

```
browser ──HTTPS(LAN)──▶ FastAPI (server/)
                          ├─ auth: argon2id password, server-side sessions, CSRF
                          ├─ REST API /api/v1  (contract: docs/API.md)
                          ├─ simulation engine (numpy): deterministic + Monte Carlo
                          ├─ import: CSV column-mapping + OFX
                          └─ SQLite (data/gol.db) via SQLAlchemy 2.0 + Alembic
web/ (Vite+React+TS) built to static assets, served by FastAPI in prod,
Vite dev server with /api proxy in development.
```

Single user, single process. No cloud calls in v1. The database and any TLS
material live under `data/` (gitignored).

## Domain model

- **Profile** (singleton): birth_year, default retirement_age, life_expectancy,
  annual_retirement_spending, social_security_monthly, inflation assumption.
- **Account**: name, type (checking, savings, brokerage, retirement, hsa,
  property, vehicle, other_asset, mortgage, loan, credit_card, other_liability),
  current balance, optional `growth_rate_pct` override (e.g. house appreciation,
  car depreciation as negative). Possessions are accounts of type property/vehicle.
- **BalanceSnapshot**: (account, date, amount) — history for net-worth-over-time.
- **Flow**: recurring income/expense/contribution. amount_monthly,
  annual_growth_pct, optional start/end dates, optional target account.
- **Goal**: dreams with target_amount, optional target_date, priority, notes.
- **Transaction**: imported line items (account, date, amount, payee, category).
  v1 uses them for spending insight and balance reconstruction; not required for sims.
- **Scenario**: named JSON param-set diffed against baseline reality: retirement
  age, monthly savings delta, one-time or recurring events ("take up golf" =
  recurring expense event), return/inflation overrides. `is_baseline` marks the
  "current trajectory" scenario, auto-derived from real data.
- **SimulationRun**: cached results keyed by (scenario hash, engine version, seed).

## Simulation engine (`server/src/gol/sim`)

Pure numpy, no ORM imports — takes a `PlanInputs` dataclass, returns arrays.

1. **Deterministic projection**: month-by-month expected path per account bucket
   (cash, invested, property, debt) from now to life expectancy. Applies flows,
   growth rates, retirement transition (income stops, spending switches to
   `annual_retirement_spending`, withdrawals from invested assets).
2. **Monte Carlo**: N paths (default 1,000; hard cap 10,000) with lognormal
   annual returns per asset class (configurable mean/vol; defaults documented in
   code: stocks 7%/15%, bonds 3.5%/7%, cash 1.5%/0.5%, real historical-ish),
   inflation as a stochastic AR(1) around the assumption. Vectorized: shape
   (n_paths, n_months). Outputs: net-worth percentile bands (p10/25/50/75/90),
   success probability (money outlives you), median ruin age when applicable.
3. Taxes are a coarse effective-rate knob in v1 (documented limitation);
   proper bracket/withdrawal-ordering modeling is a v2 item.

Determinism: every run accepts a seed; tests pin seeds.

## Security posture (LAN + password)

- First-run setup screen creates the single password → argon2id hash in DB.
- Server-side sessions (random 256-bit token, HttpOnly + Secure + SameSite=Lax
  cookie), idle timeout 7 days, absolute 30 days.
- CSRF: double-submit token required on all mutating requests (`X-CSRF-Token`).
- Login throttling: exponential backoff per source IP + global.
- TLS: self-signed cert auto-generated into `data/tls/` on first run; uvicorn
  serves HTTPS. Docs explain trusting it. Plain HTTP only on 127.0.0.1.
- Security headers: CSP (self only), X-Content-Type-Options, Referrer-Policy.
- No secrets, tokens, or financial data in the repo or logs. Import files are
  parsed in-memory and not retained.

## Feature flags & theming

`settings` table exposed via `/api/v1/settings`. `theme: "fintech" | "game"`.
The frontend theme system is CSS-variable-token based so the game theme is a
token + illustration swap, not a fork of components.
